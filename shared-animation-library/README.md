## Production contract (what each song supplies)
A production = its own folder with: the supplied master recording (full song by default) and `sourceAudioOffsetSeconds` (normally 0; nonzero only for an explicitly requested excerpt); a `config.js` (`PROJECT`: explicit `width,height`, `fps,duration,bpm,offset,seed,audio,assets,fonts,…`); scene scripts and assets; cue data converted from source time once; particle events; theme/typography/shot sequence. By default, use the master from beginning to end at its measured duration; do not shorten, trim or alter it without a separate song-specific decision. For each song, select either 4:5 (1080×1350) or 9:16 (1080×1920) from its visual direction, explain the choice before storyboarding, and compose natively for that frame. Do not crop a layout made for the other ratio. The shared renderer propagates configured dimensions through normalization, canvas sizing and export viewport, but each scene and overlay must be checked for its own coordinate/layout assumptions. Do not rely on the technical dimension fallback as the creative choice. The library supplies the engine, helpers, adapters, export planning, cache identity and supervised encoding. The current technical dimension and frame-rate defaults are 1080×1920 and 24 fps; new songs must set duration to the measured recording duration explicitly. If `maxDurationSeconds` is omitted, it resolves to that duration; it no longer imposes a global duration ceiling.

## Configuration (`base/src/project-config.js`)
`normalizeProject(PROJECT)` is the one validator/defaulter, run by core.js, the sizing script, the adapter install and `render.mjs`: finite positive integer `width/height`, positive `fps/duration/bpm`, finite `offset` (video-time downbeat), finite non-negative `sourceAudioOffsetSeconds`, safe-integer `seed`, and `duration ≤ maxDurationSeconds`. New songs set `duration` to the measured full recording. When `maxDurationSeconds` is omitted, it resolves to `duration`; an explicitly supplied shorter per-production maximum is rejected. The legacy 11-second duration fallback is for old examples and is not a new-song default. Production-specific keys pass through. Dimensions are not command-line overrides (`--fps` is the only one) so page, canvas and viewport cannot disagree.

## Shared export contract (`export/export-plan.mjs`, used by the Remotion and legacy p5 routes)
Time bases: **source** (original recording), **production** (the complete recording by default, or an explicitly requested excerpt; production 0 = source `sourceAudioOffsetSeconds`, normally 0), **frame index i** (production time exactly `i/fps`).
A local explicit range `a:b` snaps to frame boundaries: `firstFrame=round(a*fps)`, `endFrame=round(b*fps)`, `frameCount=end-first` (half up). A zero-offset full-master export instead rounds the video frame count up so frame quantization cannot make its planned video endpoint precede the measured recording; Remotion schedules the audio for the exact `PROJECT.duration`, while the planned video can end less than one frame later. Explicit ranges/excerpts retain nearest-frame bounds and frame-bounded audio. The Remotion plan reports the selected audio span, video frame count and endpoint difference; this no-media plan does not prove actual encoded endpoints or synchronization. Do not trim, pad or speed-change the master to fit the video frames. Cue source→video conversion snaps to 1e-9 s. Audio comes from `PROJECT.audio` (relative to the production config); p5 legacy commands may also accept `--audio` relative to the working directory.
`node base/render.mjs --root=<prod> --plan [--clip|--encode] [--range=a:b]` prints the effective plan, identity and ffmpeg arguments with no Chrome and no media.
Frame cache: `out/<entry>-<identity12>/frames/` + `manifest.json` (identity, dimensions, fps, jpeg quality, interval, frame count, soundtrack offset/start/duration, hashed closure files, external URLs). Identity = sha256 over the entry page, its local scripts/stylesheets, every transitively imported local module, normalized PROJECT, declared assets/fonts, output settings and package-lock + installed p5/p5.brush versions — not the repository collection, not audio. Resume only if identity/size/fps/entry/quality match, otherwise an explicit mismatch error; encoding looks only at the selected sequence. Google Fonts CSS is external and unhashed (listed in the manifest).
Failures: ffmpeg handlers attach at spawn; failed startup, nonzero exit, signal, broken input pipe and exit before input ended all stop feeding, remove the `.part.mp4`, and exit 1 with the encoder's stderr tail; success is reported only after exit 0 and the final rename. Saved frames are never deleted.

## Production use
1. Start at the shared front door and set an explicit engine in each new song's config:
   - **Standard route for new song productions: Remotion.** Set `renderEngine: 'remotion'` and `remotion: {scenes:'remotion/scenes.jsx', publicDir:'public'}`. Write that song's scenes as React components exported from the named `scenes` object in `remotion/scenes.jsx`; schedule them with `PROJECT.scenes` and optional `PROJECT.overlays`. Put the unchanged recording, images and fonts under the production's `public/` folder and refer to them through `PROJECT.audio`, `assets` and `fonts`. Read `remotion-runtime/README.md` for the component props, timing contract and commands. P5 `PROJECT.modules` do not load React scenes; adapt selected mechanisms intentionally.
   - **Legacy route for existing productions: p5.** Omitted `renderEngine` remains `p5`. For the declared-module workflow, use `PROJECT.modules` + `PROJECT.scenes`; `installProduction` loads scripts/ES modules in dependency order and no per-scene script tags are added. The older direct-script-tag route remains documented for its existing productions only. A scene module must load through one route only.
2. For either engine, each new song sets `width`, `height` and measured full-recording `duration` explicitly. Choose 4:5 (1080×1350) or 9:16 (1080×1920) before storyboarding; the validator's 1080×1920 and 11 s fallbacks are technical legacy values, not creative or production defaults. Omitted `maxDurationSeconds` follows the duration; an explicit per-song maximum is opt-in. Do not select an excerpt without the user's request.
3. Print a no-media plan first with `node shared-animation-library/render.mjs --root=<production> --plan`. Open Chrome, save stills or render the complete song only at the currently authorized stage. The shared front door refuses output overwrite and paths outside the production folder. Existing p5 outputs and source stay on the p5 engine.

## Production declaration (`PROJECT`, validated by `normalizeProject`) — added 2026-10-25
All cue and scene times are PRODUCTION seconds (local to the full recording by default, or to an explicitly requested excerpt; 0 = source `sourceAudioOffsetSeconds`).
**Coverage behavior (runtime):** production coverage is the half-open interval `[coverage.start, coverage.end)` (default `[0, duration)`). For `t < coverage.start` or `t >= coverage.end` the production never calls a scene's `draw` or `overlay` (the base host shows its ordinary background); at an internal scene boundary the later scene is active. `timeline.js` is unchanged: the guard lives in the shot functions and the overlay layer.
- `productionId` (required with scenes) names outputs/caches. `modules: [{id, src, type:'classic'|'module', requires:[]}]` — scene/mechanism scripts, paths relative to `config.js`. The derived `moduleLoadOrder` is a stable topological order (declaration order breaks ties); cycles, unknown requirements and duplicate ids are refused.
- `scenes: [{id, start, end, impl?, needs?, params?}]` — contiguous, no overlap or gap, each ≥ one frame, `end ≤ duration`; they must cover `coverage` (default `0..duration`) exactly. `impl` (default = `id`) names a registered scene implementation.
- `cues: {entries:[…]} | {module:'cues.mjs'}`; `assets: [path | {id, src, kind:'image'|'data'|'other'}]`; `fonts: [path | {family, src, weight, style, unicodeRange}]`. Absolute paths, URLs and backslashes are refused. `maxDurationSeconds` is an optional per-production limit; when omitted it resolves to the configured `duration`.
- Page: `base/studio.html` (and the example) chain `installLibraryOverlays(...)` → `installProduction(window, normalizeProject(PROJECT), {configUrl})` in ONE `READY_PROMISES` entry. With scenes declared, do not add per-scene script tags.

### Scene implementation (`registerSceneImpl(id, impl)` from a classic script, or `export const scenes = {id: impl}` from an ES module)
`{draw(st), overlay?(ctx, st), init?(env), dispose?(env), seek?(st)}`. `draw` paints the whole frame and must be a pure function of `st`. `overlay` is a crisp Canvas2D layer in native screen pixels (above grain, below karaoke), called only while the scene is active; this is how canvas mechanisms (R06 critter, particles) are used from ordinary scenes. `init` runs once after modules, cues, fonts and assets are ready; `dispose` runs in reverse order, also to roll back a failed init. A scene that keeps frame history must define `seek(st)`, called before every draw/overlay; otherwise it must be stateless (frames render out of order).
`st` (frozen): `t` (authoritative production time), `localT`, `duration`, `frame` (round(t·fps), informational), `sourceT` (master time), `sceneId`, `sceneIndex`, `fps`, `width`, `height`, `params`, `cues`.
Failures are `ProductionLoadError` (`stage` = module | cues | font | asset | impl | init, `id`); `host.PRODUCTION_ERROR` records it, and core.js therefore never sets `window.ready`. On failure `installProduction` restores `host.registerSceneImpl` (prior value or removed), removes its overlay layer, disposes a dispatcher it created and any initialized scenes; a pre-existing dispatcher and its layers are untouched. Success-only registration is ordered so nothing after the last fallible step can fail: overlay layer, pagehide listener, `shots()`, then `host.PRODUCTION` last; failure restores the prior `PRODUCTION` state (including absence) and removes a registered pagehide listener. Verified for module-load failure, a `host.addEventListener` failure after scene init, and a `host.shots` stub that throws, on fresh and preconfigured hosts. "No shots installed after a failed install" is established only for the tested failures before shot registration and for a `host.shots` stub that throws before changing state; a failure after `shots()` has partially mutated its host cannot be rolled back by this installer. `shots()` has no unregister, so it is not claimed to be fully transactional.

### Cues (`production/cue-schema.mjs`)
Entry `{id, kind, basis:'source'|'production', seconds, endSeconds?, evidence, tool?, confidence?, text?, textSource:'supplied', confirmedBy?, data?}`; `evidence` ∈ measured | estimated | inferred | supplied | confirmed (confirmed needs `confirmedBy`). Lyric TEXT is supplied material; its TIMING evidence is separate. `normalizeCues` converts source→production once through `numeric/timebase.mjs`, keeps both clocks, refuses already-converted input, and returns an index (`between`, `active`, `nextAfter`, `lastAtOrBefore`, `byKind`, `overlapping`). `fromBeatgridAudiomap` (R04) and `fromAudioJson` (R07) produce raw `estimated` source-clock entries; their input shapes were taken from the source code, not from real analysis output.

### Mechanism: R06 critter rig (`adapters/r06-critter-rig.mjs`)
`createCritterRig({poseTrack, gaitRate})` → `{poseAt(localT), draw(ctx, st, {x, groundY, scale})}`. Inputs: scene-local keyframes (numeric pose fields smoothstep-eased, discrete fields held, `run:true` gait = gaitRate·t); output layer: the overlay `ctx` in screen pixels; clock: `st.localT`; stateless and seekable. Example call site: `examples/neutral-production/scenes/scene-b.mjs`.

### Assets and fonts
Declared files are hashed into the frame-cache identity (modules and the cue module with their own import closures; assets; fonts) and loaded before ready: fonts through `FontFace` + `document.fonts.add`, `image` assets through `Image.decode`, `data` assets as ES-module default exports (file:// `fetch` is unavailable), `other` assets as resolved URLs only. `production/fontsource.mjs fontsourceFaces({packagesDir, pkg, weight, style, subsets, configDir})` turns the locally installed @fontsource CSS into `fonts` entries; it reports the package's declared `unicode-range`, not verified glyph coverage.

So this automatic startup draw very likely called the opening scene's draw path once in the hidden p5 canvas. That is inferred from the source; it is not a recorded browser observation and not evidence the scene looked correct.

**Distinct from `renderAt()`:** the startup draw is not an explicit `renderAt()` call. `renderAt()` / `composite()` (the 2D `#out` composite, grain and overlay hook) was never run, and no final composite or saved still was produced.
