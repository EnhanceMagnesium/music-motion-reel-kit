Reviewed numeric/numeric.mjs, numeric/timebase.mjs and numeric sections of tests/verify.mjs against helper-compatibility.txt. Focused Node imports/probes only; no source changes, native canvas, browser or media. No P0/P1 findings; arithmetic and named variants inspected match the source formulas.

[P3] Original-short-name namespace exposes a changed beatPulse signature without saying so at the namespace
File: shared-animation-library/numeric/numeric.mjs:62 (definition at49; header at60)
Source R02 beatPulse(t,k=7) closes over BEAT, whereas r02.beatPulse aliases beatPulseR02(t,beatSeconds,k=7). A source call r02.beatPulse(.25) returns NaN; migrating beatPulse(.25,3) at120bpm returns .5580351457700471 rather than .22313016014842982, because 3 becomes seconds-per-beat. The explicit exported beatPulseR02 API is intentionally parameterized (comment48), so this is an API/documentation hazard in the namespace described as preserving original short names, not an error in its formula. Recommend documenting the namespace signature exception adjacent to r02 or leaving only the explicit beatPulseR02 export / adding a tempo-bound namespace factory. tests/verify.mjs:122 checks the explicit three-argument API, so it does not establish namespace call compatibility with the original closure.

[P3] Time conversions validate operands but can return Infinity; frame index permits unsafe integers
File: shared-animation-library/numeric/timebase.mjs:7-12
Focused probes: frameToVideoSeconds(1,Number.MIN_VALUE) -> Infinity; videoToSourceSeconds(Number.MAX_VALUE,Number.MAX_VALUE) -> Infinity; sourceToVideoSeconds(Number.MAX_VALUE,-Number.MAX_VALUE) -> Infinity. All operands satisfy current validation. Number.isInteger accepts 2**53, where adjacent frame identities can no longer be represented. These cases are far beyond normal film inputs and are not blockers for this draft. If this is advertised as a strict validated time API, require safe integer indices and validate finite outputs. tests/verify.mjs:129 covers negative/fractional frames and zero fps but neither overflow nor unsafe integer acceptance.

[P3] The 'bit-identical' assertion treats signed zero as equal
File: shared-animation-library/tests/verify.mjs:95-96
The comparator Object.is(a,b) || a===b accepts +0 versus -0, though Object.is rejects them and reciprocal sign differs. This does not demonstrate a known mismatch in the current formulas; it weakens the advertised bit-identical evidence. Recommend Object.is alone for exact numeric comparison (it already accepts NaN against NaN), plus explicit signed-zero probes where the contract claims bit identity. Also use 'all compared aliases on sampled inputs' rather than 'for every named alias': r02.beatPulse is not directly compared in this check, and the namespace short-name compatibility is an intentional API adaptation.

NO CHANGE RECOMMENDED FOR SOURCE-COMPATIBILITY INVALID INPUTS
seg zero-width NaN; Park–Miller modulus-zero stream; unvalidated/empty exposure tracks; out-of-order exposure selection; pre-first-entry behavior; negative beatPulse remainder; unsigned/signed noise and back arithmetic grouping all deliberately preserve original sources. Adding strict validation to these functions would change compatibility and should use separate wrappers. The prepared numeric module correctly keeps R02 kinetic1.7/painted1.9 and R03/R061.8 back curves distinct, R03/R06 noise evaluation order, Mulberry32 and Park–Miller, unary and window ss APIs, and track-relative exposure epsilon. Pure geometry/interpolation helpers omitted from this small core are documented candidate modules, not accidental changed behavior.
