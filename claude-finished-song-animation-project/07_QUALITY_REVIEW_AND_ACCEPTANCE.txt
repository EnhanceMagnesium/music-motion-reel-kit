# QUALITY REVIEW AND ACCEPTANCE — FULL-SONG REMOTION PRODUCTIONS

Use this guide for a song-specific candidate after the relevant implementation and media-render stages have been authorized. It is a compact, evidence-based review process for the complete song. It replaces blanket instructions to render a frame every half second, perform repeated full exports, or continue until the result is “perfect.” Do not render or create review media unless the current conversation authorizes that stage.

## Audible lyrics and visual treatment

When a song is designed without on-screen lyrics, or a tool cannot produce the requested lyric display, follow the audible-lyrics visual treatment in `PROJECT_INSTRUCTIONS.md`. When captions are requested and only some lines can be displayed, inspect the permitted displayed lines for exact wording, timing, legibility and placement; use visual action for omitted passages. Honor an explicit no-caption direction. Review visual storytelling, the preserved master, actual sound playback and audiovisual sync as separate evidence. Describe the resulting caption treatment and any impact on accessibility or requested deliverables. A still or silent frame sample cannot verify what is heard.

## 1. Keep the review tied to this song

- Use only this conversation’s supplied recording, lyrics, creative brief, production plan, config, assets and named song folder for song-specific conclusions. Treat earlier productions as technical examples.
- Confirm the selected native frame (4:5 at 1080×1350 or 9:16 at 1080×1920), measured full-recording duration, frame rate, scene schedule and audio path from this song’s `PROJECT` config and source files.
- The whole recording is the default. A shorter excerpt, altered ending, added hold or changed master requires a separate song-specific decision.
- Keep renderer readiness, sampled-frame inspection, motion review, technical export checks and the user’s creative acceptance as separate conclusions.
- Read `storyboard/STORYBOARD.md` and linked boards as the intended visual coverage. A pre-code board expresses intent; stills show sampled rendered appearance; candidate playback is needed to judge motion over time.

## 2. Confirm the plan before spending render time

Read the project instructions and the shared Remotion README. Use the single connected kit and run route:

```sh
node shared-animation-library/render.mjs --root=productions/<song> --plan
```

The plan is a no-media check, not a visual or audio review. Confirm that it reports this production’s intended engine, dimensions, fps, full duration, frame count, audio source, and scene schedule. Check that scenes and overlays cover the intended full interval; text, cues, and asset paths belong to this song; and no output path would overwrite existing work. Resolve plan or source inconsistencies before rendering.

## 2a. Confirm archival footage is part of the production

Every finished song must include at least one relevant, reviewed, rights-cleared clip from each of the Moving Image Archive, Wikimedia Commons and Internet Archive (Prelinger when a suitable item exists). Read `10_MOVING_IMAGE_ARCHIVE_WORKFLOW.txt` and `15_MEDIA_API_DISCOVERY_WORKFLOW.txt`; confirm each selected clip is in this song’s `public/archive/`, declared/resolved in scene assets, recorded in its applicable provenance manifest, and scheduled in the actual Remotion composition. Do not force unrelated footage: if a source has no suitable clip, record its requirement unmet and do not call the reel finished. `--stills` uses Remotion’s headless Chrome renderer for pre-export scene stills. After an authorized complete candidate exists, use the dedicated Playwright MP4 review in `11_HEADLESS_BROWSER_FRAME_REVIEW.txt` to decode and capture a compact, risk-based sample that includes footage moments from all three sources; FFmpeg makes the contact sheet. Use sampled frames to check crop, aspect fit, image condition and caption overlap. Confirm source audio is muted and transitions work during authorized full-candidate playback with sound. A successful `--plan`, browser load, FFmpeg probe or contact sheet alone is not proof of visual acceptance, motion quality, or audiovisual sync.

## 3. Use a risk-based still set, not half-second sampling

After still output is authorized, choose timestamps from the actual scene and cue schedule. Render only the frames that answer a review question. Use the shared entry, for example:

```sh
node shared-animation-library/render.mjs --root=productions/<song> --stills=<comma-separated-seconds> --out=review/stills-round-01
```

Use the pre-code visual storyboard as a coverage map when selecting samples. Check the key action states that carry the greatest risk, but do not render every storyboard panel automatically; preserve the distinction between intended boards and sampled output.

Build the smallest set that covers:

1. The opening image and the ending image.
2. At least one representative frame from every distinct scene or materially different scene state.
3. Each distinct overlay, typography treatment, camera/framing mode, and major visual motif at least once.
4. Important lyric or title states, including the longest or densest text and any change in placement or hierarchy.
5. A frame immediately before, at, and after a transition only when its blend, mask, camera move, overlay handoff, or timing makes it visually risky. For a simple cut, the scheduled scene frames plus normal-speed playback usually answer the question.
6. Any specific fix from the previous review, sampled at the same timestamp for comparison.

Use the configured frame rate when choosing adjacent-frame timestamps. Include a scene’s beginning, peak, or ending as additional samples only when one representative frame cannot show its meaningful state changes. If the production has many pre-render stills, group them only with an already available tool; keep original full-resolution stills for type, edge and crop checks. Do not install a separate contact-sheet dependency or change the renderer. Post-render Playwright samples and their FFmpeg contact sheet follow `11_HEADLESS_BROWSER_FRAME_REVIEW.txt`.

If the production agent chose a HyperFrames Player subcomposition for a scene, include its opening, a representative middle state and ending where those answer a visual question. For a newly introduced or high-risk child integration, request a non-chronological or repeated frame through the focused technical check to exercise seeking/readiness; do not add a full duplicate scene sample set when existing evidence already covers it. Inspect the child at the song's native dimensions. The isolated `remotion-hyperframes-hybrid` fixture proves only its synchronous example; consult `14_HYPERFRAMES_SUBCOMPOSITION_GUIDE.txt` for limits. A successful still is not proof of future frames, encoded output or sync.

Do not make a uniform still every 0.5 seconds the default. It produces many images without proving smooth movement. A short, issue-focused set is cheaper and easier to compare. Still images establish appearance only at their sampled times.

## 4. Headless browser check of the rendered candidate

After a full candidate is rendered under the conversation’s authorization, a Claude Code Desktop task may use its local Browser pane (“Browse with Claude”) as an interactive visual preview. This subsection applies only to Claude Code Desktop; Codex tasks do not use that pane. In Claude, open the candidate video by clicking its path in the conversation; inspect the visual presentation and seek to questions that remain. This is a companion preview, not the saved QA record. If the pane is unavailable, record it as unavailable rather than changing environments or substituting another browser.

Then follow `11_HEADLESS_BROWSER_FRAME_REVIEW.txt`. Select the same risk-based timestamps used to answer the review questions, including every distinct scene and type treatment, selected archival footage, opening/ending and any risky boundary or correction. The Playwright helper captures browser-decoded MP4 frames and writes a candidate hash, browser metadata, diagnostics and FFmpeg contact sheet inside the song folder. Inspect both the contact sheet and the original PNGs. This checks browser decoding and sampled frame presentation only; it does not verify audio, synchronization, motion between samples, or creative acceptance. Neither the Claude Browser pane nor Playwright proves that the executing agent heard the soundtrack. Preserve the exact command and exit status, and review the full candidate with sound separately.

## 5. Review motion and the song as motion

After a complete candidate video has been authorized and rendered, watch the entire candidate at normal speed with sound once. This checks the complete visual arc, not every frame. Then replay or scrub only the passages where the first viewing found a question or defect.

Assess:

- Whether the visual arc follows this song’s actual musical and lyrical development, changes of energy, instrumental space, and ending without forcing a repeated visual trick.
- Whether movement has a clear purpose, readable anticipation and resolution, suitable speed, and convincing depth; check holds, acceleration, easing, camera motion, transitions, and repeated cycles during playback.
- Whether cuts, changes, reveals, and emphases meet the recording’s real cues. Do not infer synchronization from a still or a declared cue list. Confirm timing by listening to the rendered master.
- Whether the first moments establish a strong focal point and the ending resolves with the music, without adding unwanted silence or extending beyond the supplied master.

If playback is unavailable, the audio is missing, or sync cannot be judged reliably, record that limitation. Do not label audiovisual review complete.

### Temporal integrity before word-level lyric polish

When the candidate uses animated grain/turbulence, SVG filters, nested effects, frame-sensitive overlays or has any reported flicker/dropout, run the shared temporal scan on the complete encoded file before tuning word-by-word lyric reveals. Follow `18_TEMPORAL_STABILITY_AND_WORD_TIMING.txt`; the helper is `shared-animation-library/quality-review/temporal-stability-scan.mjs`. Review any candidate frames in contiguous neighbor sequences and use normal-speed playback to distinguish intentional action from a defect. A single-frame still set and sparse Playwright captures can miss these artifacts. If a multi-worker-only defect is suspected, compare the same source/config with `--workers=1`, changing one variable at a time. Do not change the shared worker default from one song’s result.

After the temporal pass, align word-level captions only when the song’s chosen treatment or the user’s request calls for them. Keep supplied lyric text authoritative; document aligner estimates, signal cross-checks, interpolations and listening confirmation separately. Word cues do not mechanically set scene cuts. The guide and `repository-preparation/templates/WORD_TIMING_REPORT_TEMPLATE.md` define the evidence record. If listening is unavailable, do not call word timing confirmed.

## 6. Apply a consistent visual-design checklist

At the selected native frame and at a phone-sized preview, review every distinct scene and overlay for:

- **Story and focus:** one clear idea per moment; a legible focal hierarchy; images and symbols suited to this song’s words, mood and theme.
- **Footage and code action:** review planned clip seconds separately from visible frame share and prominence. Check each footage-bearing scene for a concrete code-built action that advances the song, and whether code-led focal moments carry the larger arc. A smaller viewport alone is not proof of a better balance, and borders, tints, captions or texture alone are not story-carrying animation. Preserve the selected clip choices and duration when the issue is composition. Refer to `17_FOOTAGE_FRAME_FOOTPRINT_AND_CODE_ACTION.txt`.
- **Composition:** native framing for the chosen ratio; balance, negative space, scale, depth, edge clearance, platform interface-safe areas, and deliberate camera placement. Never treat a layout made for the other ratio as finished by cropping or resizing it.
- **Typography source and evidence:** Follow `20_FONT_DISCOVERY_AND_LYRIC_TYPOGRAPHY.txt`; check actual loaded family/weight, script shaping and required glyphs, representative lyric states and the song font record. Metadata alone is not visual verification.
- **Typography:** correct supplied words and spelling; readable size, line breaks, contrast, tracking, placement and dwell time; lyric emphasis supports rather than competes with the image.
- **Color and finish:** coherent palette, controlled texture and effects, consistent lighting/material cues, clean edges, and enough variation to sustain the full song. The palette must be this song's own choice, not a Claude-orange, house or prior-song default; judge contrast, hierarchy and readability only from reviewed images.
- **Motion and transitions:** judge actual playback, not sparse stills. Check visual continuity, direction, timing, scene entrances/exits, overlap behavior, and whether effects obscure meaning.
- **Coverage and variation:** every scheduled scene, text state, cue-driven event and overlay has a defined purpose and adequate screen time; look for accidental gaps, repeated compositions, dead holds and abrupt endings.

Review type and critical shapes at full output size; use phone-size viewing to judge hierarchy and legibility. A sample still does not establish behavior between samples.

## 7. Separate technical checks from creative acceptance

For the final candidate, record evidence separately for:

- **Configuration and plan:** chosen engine, dimensions, fps, measured source duration, planned frames, scene coverage, and export plan.
- **File and stream checks:** output path, successful command/exit status, video dimensions and frame rate, decoded frame count/duration, audio stream presence, and any encoding or decoding errors. Use available local tools; report commands and actual results.
- **Temporal stability:** scan parameters, candidate path/hash, decoded frame count, suspected frame indices/times, contiguous-frame inspection and any controlled render comparison. A zero heuristic count is limited to that detector and does not prove all flicker is absent.
- **Audio/video alignment:** source recording used, source and output endpoints, declared offset, frame-quantization difference, and what was checked by listening. A matching duration or present audio stream alone does not prove synchronization.
- **Visual review:** sampled still timestamps and reviewed scenes/states, plus whole-candidate playback status.
- **Creative decision:** accepted by the user, awaiting the user, or returned for changes. Technical success is not creative acceptance.

Do not claim font, glyph, asset, overlay, browser, performance, encoding, or synchronization verification unless that specific behavior was exercised and evidence is available. Name the exact fixture or production used. The eight-second synthetic examples are renderer fixtures; they do not verify a finished song’s full duration, sound sync, or visual quality.

## 8. Keep iteration bounded and actionable

For each review pass, create a short issue list with timestamp/frame, scene or overlay ID, category, observed evidence, impact, proposed correction, and status. Separate:

- **Blocking:** wrong or missing required song content, broken scene/overlay, unreadable essential text, incorrect frame/duration/audio, serious sync error, failed export, or major composition flaw.
- **Important:** a clear weakness in hierarchy, pacing, movement, transition, consistency, or song-specific storytelling that materially lowers quality.
- **Polish:** optional refinements that do not prevent a coherent, readable, technically correct reel.

First pass: inspect the risk-based still set and the authorized complete candidate, then prioritize blocking and important issues. Make only corrections supported by an observed issue. For the next comparison, render stills for changed timestamps and affected boundaries; do not rerender the whole video for a local still-only correction. Once the scene changes are stable, render one complete updated candidate when authorized and review it at normal speed with sound. Recheck the relevant stills and technical output facts.

Stop when all blocking issues are resolved, important issues are resolved or explicitly accepted by the user, and the evidence required for the intended stage is recorded. Do not promise perfection or run an automatic endless critique loop. Report remaining polish ideas separately so the user can choose whether they are worth more time or render cost.

## 9. Review record

Save a concise review note inside this song’s own `productions/<song>/review/` folder when that folder/output is authorized. Include candidate identity/path, config and audio identity, selected frame and duration, plan and render commands/results, still timestamps, temporal-scan JSON and interpretation, word-timing evidence when used, issues and changes by pass, full playback status, unverified areas, and the user’s acceptance status. Keep production media and review evidence out of shared examples. Never overwrite a prior candidate or review record without explicit direction.

AUTHORIZATION CONTINUITY
A single initiating user instruction may expressly authorize multiple named stages, including the full production. Apply its scope throughout that song without repeated approval for the same work. Retain separate evidence and acceptance conclusions for each review stage. This guide alone does not authorize media production.


AUTHORIZATION IN A SINGLE INITIATING PROMPT
The single canonical prompt `05_NEW_SONG_CONVERSATION_PROMPT.txt` can authorize the no-media plan, pre-export stills, complete candidate render, installed Playwright/FFmpeg review, full playback and bounded corrections for that named song together. When submitted, carry out those named stages without requesting the same approval again. This does not authorize costs, credentials, uncertain rights, external publication or unrelated work. If a required capability is missing, state the exact execution boundary; do not reinterpret it as lack of user authorization.
