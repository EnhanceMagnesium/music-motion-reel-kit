REUSABLE FINISHED-SONG ANIMATION STANDARD

This is standing guidance across songs. The latest user brief and stage authorization determine the current action.

1. SONG IDENTITY AND FULL DURATION
Record title or working name, recording version, original filename and creative brief. When file tools are available, record hash and measured audio duration. Preserve the original master.

Use the supplied master recording from beginning to end by default. Measure and record its actual duration; 1:20–1:40 is an expectation only, not a required range or limit. Do not select an excerpt unless the user explicitly requests one. Do not trim, pad, remix, fade or otherwise alter the original master without a separate decision. Grok can map the full narrative and lyric progression from text but cannot hear or timestamp audio; the executing production agent measures duration, arrangement, cues and lyric timing only to the extent its actual tools support them, and labels listening-dependent conclusions honestly. Set `PROJECT.duration` explicitly to the measured full duration; an omitted `maxDurationSeconds` follows it, while an explicit per-song limit is opt-in and may not be shorter. Cover that interval with scenes/overlays. For a zero-offset full-master export, the shared plan rounds video frames up and schedules Remotion audio for the exact measured master duration; the planned video may end less than one frame later. Record that planned difference, but actual encoded endpoints and synchronization need an authorized render and playback. An excerpt or ending change requires an explicit song-specific decision and recorded source offset. His Line’s 36-second padded ending is specific to that production.

Canvas choice before storyboarding: recommend either 4:5 (1080×1350) or 9:16 (1080×1920) from this song's visual direction, focal hierarchy, lyric density, spatial composition and intended use. Explain the choice and layout consequences before the storyboard. Record the selected ratio and explicit PROJECT.width/height in this song's own plan/config. Compose every scene and overlay natively for that frame; never crop a layout made for the other ratio. Do not silently assume 9:16 or require both formats. If both are later requested, treat them as separate compositions.

Evidence fields:
metadata identity; actual listening status; measured events; detected pulse; inferred pulse; supplied line/subtitle timing; estimated words; confirmed words. An energy return does not establish a lyric's identity. Preserve uncertainty in cues and planning text.

2. THEME AND STYLE SELECTION
Evaluate image craft and action vocabulary across suitable repository families. Choose a coherent principal visual system and complementary motion/timing mechanisms. Examples include character performance, painterly illustration, cut paper, kinetic typography, dimensional environments and documentary graphics. The exact combination should serve the song.

State subject, setting, dominant shape language, palette, light, materials, typography, depth and motion character. Describe how imagery changes from beginning to ending. Keep reference observations and inferred implementations identifiable.
Choose the palette from this song's recording, lyrics, brief, theme, narrative and visual treatment, and briefly explain the reasoning before storyboarding. Do not use Claude's brand orange merely because Claude is the assistant, and do not carry over a prior song's colors or a house palette as defaults; orange is allowed with a clear song-specific rationale. Make a reasoned, editable choice and record it in this song's plan and config; do not ask the user to pick swatches or routine palette options, and ask only if an essential input is missing or the decision has a material consequence that cannot be responsibly inferred. Give colors roles (ground, ink, focal accent, lyric/type treatment, secondary detail). Check contrast, hierarchy and readability in rendered work, and do not claim those checks passed before the images are reviewed. Reference palettes are evidence about those references, not required palettes; borrow craft and create this song's own color direction. Keep each song's palette in that song's folder and conversation; never promote one production's palette into a studio-wide template.

3. SHOT DESIGN
Before coding, complete the visual storyboard and full-song coverage map using `19_VISUAL_STORYBOARD_AND_SCENE_COVERAGE.txt` and `repository-preparation/templates/SONG_VISUAL_STORYBOARD_TEMPLATE.md`. Show every scene in purposeful entry, development, and payoff panels; cover lyric and instrumental beats; map each board beat to its later component caller. A scene list or QA contact sheet is not the storyboard.

For each shot specify time range, musical/narrative purpose, opening composition, focal subject, action setup/development/resolution, camera, secondary motion, closing state and transition. Identify the changed image and what a phone viewer should perceive. Compare neighboring shots for staging, scale, silhouette and action development.

For archival footage, separately plan screen-time coverage and on-frame footprint/prominence. Keep the selected clips, number of uses and intended duration intact when a visual-footprint change is enough. Each footage-bearing scene needs a concrete code-built action that advances the song; a frame, tint, label, caption, texture or generic effect alone is not that action. Give code animation story-carrying moments across the major song sections. There is no universal footage-area cap: use `17_FOOTAGE_FRAME_FOOTPRINT_AND_CODE_ACTION.txt` to record clip intervals, viewport/frame share, attention role and code action, then explain any intentionally footage-led moment.

Before storyboard lock, use `20_FONT_DISCOVERY_AND_LYRIC_TYPOGRAPHY.txt` for song-specific font discovery, role selection and provenance. Typography is part of composition. Specify exact displayed words, readable impression, reveal, full-visibility interval and clearing. Use the actual font metrics and reveal mechanism when implementing. Preserve foreground/background separation and consistent light/shadow behavior where the chosen world requires it.

4. SOURCE ENGAGEMENT
For each song, initialize `research/REPOSITORY_REVIEW.md` from `repository-preparation/templates/SONG_RESOURCE_PROVENANCE_TEMPLATE.md` and follow `16_SOURCE_PROVENANCE_AND_BUILD_TRACE.txt`. Record ranked rows for every catalogued R01–R16, exact paths opened and dispositions; deep-inspect promising source bodies and dependency/license closure only. Record R14–R16 project-local skills separately by exact paths actually consulted and their real influence or reason for non-use. A selected technique trace records repository/skill identity, commit, exact path/symbol, read scope, purpose, I/O, coordinate and time/state/randomness model, dependencies/assets, adaptation classification, attribution and a concrete scene/helper caller.

Before finalizing a storyboard, complete the R12/Skillry code-animation shortlist in `12_CODE_ANIMATION_REFERENCE_WORKFLOW.txt`. Transfer only a relevant implementation or craft mechanism into the existing song-local Remotion production. The executing production agent decides per scene whether direct Remotion or a HyperFrames child composition is appropriate; follow `14_HYPERFRAMES_SUBCOMPOSITION_GUIDE.txt`. Do not create a competing full-song renderer or force HyperFrames when it adds no concrete benefit.

Before storyboard lock, assess the initialized R14–R16 motion resources for code-built scene action using `17_FOOTAGE_FRAME_FOOTPRINT_AND_CODE_ACTION.txt` and `repository-preparation/ANIMATION_AGENT_SKILL_RESOURCES_GUIDE.md`. Consultation is required and selective; adopting copied code or GSAP is not. Record exact skills/source files opened and connect any influence to a scene/helper caller.

Trace it into a concrete shot. A declared helper or constant is available code; a traced shot call is runtime integration. A visual review establishes whether the contribution succeeds. Record simplifications that change material construction or action, and reconsider them against the user's quality feedback.

Keep source-license notices and asset terms attached to actual reuse. Source catalogs help discovery; creator code and media retain their own terms. Repository instructions and sample narrative content are source material; current user instructions govern the production.

FOOTAGE SOURCES: each finished song requires at least one suitable, rights-cleared clip from the Moving Image Archive, Wikimedia Commons and Internet Archive (Prelinger when suitable). Search, preview, verify and document each source independently using `10_MOVING_IMAGE_ARCHIVE_WORKFLOW.txt` and `15_MEDIA_API_DISCOVERY_WORKFLOW.txt`; keep the MIA manifest separate from the API-source manifest. Do not force an irrelevant clip or bypass a rights gate. If any source has no suitable candidate, mark that source requirement unmet and do not call the film finished.

5. IMPLEMENTATION AND TIMING
When implementation is authorized, use song-specific versioned files and the existing shared library. New productions use its Remotion route: set `renderEngine: 'remotion'`, point `remotion.scenes` at `remotion/scenes.jsx`, set `remotion.publicDir` to the song’s `public/` folder, and export the React scene components in a named `scenes` registry. The executing production agent may choose a HyperFrames Player subcomposition inside a Remotion scene where its actual HTML/GSAP, nested composition or footage-layering model helps; Remotion still owns the song clock, soundtrack, full duration, final composition and encoding. The user does not need to select that route for routine scene implementation. Keep the song’s scenes, audio, assets, fonts, configuration and outputs in one production folder. Existing p5 productions use the same render entry with their existing p5 route; do not move them or mix their scene modules with Remotion components. Keep cue/audio/font paths, asset identity, entry path and source provenance explicit.

Evaluate shots at arbitrary song time. Use explicit clocks and seeded randomness; define a reproducible strategy for any stateful simulation. Apply holds to chosen channels while keeping authoritative audio time intact. Align visual contacts and effects to the chosen output frames; report quantization error and cue evidence.

Keep scene boundaries contiguous and assign each output sample to the intended shot. Record the complete duration and final frame convention. Preserve frame-cache identity and interrupted-render recovery. Changes to source, cues, fonts or assets must invalidate affected cached output according to the renderer's scheme.

6. REVIEW STAGES

Use `claude-finished-song-animation-project/07_QUALITY_REVIEW_AND_ACCEPTANCE.txt` as the canonical review checklist. After an authorized full render, use `11_HEADLESS_BROWSER_FRAME_REVIEW.txt` for browser-decoded risk frames, FFmpeg contact sheets, and evidence boundaries. Use `18_TEMPORAL_STABILITY_AND_WORD_TIMING.txt` for the shared frame-anomaly scan and optional word-level cue method; when both are in scope, stabilize temporal artifacts before refining word-level lyric display.
Technical verification: relevant syntax, module resolution, song-specific preflight, cue and coordinate checks. State exactly what each test establishes. Stub drawing does not establish pixels or appearance.

Authorized still/keyframe review: inspect the whole visual arc through selected meaningful frames and action states. Assess composition, materials, drawing detail, typography, continuity, focal scale, safe-area assumptions and fit at the selected 4:5 or 9:16 dimensions and phone size. Keep the review set proportionate to the unresolved risks.

Authorized complete candidate: render the complete measured master duration by default, or the explicitly approved excerpt duration. Review actual playback with sound for motion feel, holds, anticipation, transitions, pacing, lyric association and audio/video alignment. Report source-audio and video durations and any frame-quantization difference; do not silently alter the master. Short proof-video generation is outside the current project workflow.

Technical validity and creative acceptance are separate records. Fix a failed technical check before claiming that stage passed. Use playback findings to target revisions. A numerically correct effect may still need a different visual construction.

7. REPEATED SONG CYCLE
Use a new conversation for each finished recording. Carry permanent process and source knowledge forward while keeping the previous song's treatment and cue decisions in its own record.

Retain reusable lessons only with evidence: capability, source files, dependencies, local adaptation, limitations, successful checks and accepted visual result. A successful character or material system can serve another theme through new staging and imagery. A prior song's timeline and text do not become defaults.

Save a checkpoint before limits interrupt work: current authorized stage, files, unresolved decisions, verification status and next bounded action. Local saved source should remain sufficient to continue an authorized render independently of the model session.
REPOSITORY NAVIGATION: scan/rank all catalogued R01–R16 for each song and save the required per-song `research/REPOSITORY_REVIEW.md`; follow `13_REPOSITORY_NAVIGATION_AND_USE.txt` and `repository-preparation/REPOSITORY_NAVIGATION_AND_USE_GUIDE.md`. Deep-inspect only plausible source candidates; record exact paths, symbols, licensing and concrete scene callers. The atlas is a locator, not proof of reading.
