ONE-PROMPT FULL-SONG PRODUCTION — PROJECT REQUIREMENT
Updated 2026-10-26

INTENDED OUTCOME
The user supplies one initiating prompt and the finished recording, lyrics and any optional brief in a new song conversation. That prompt should be sufficient to carry the production through planning, implementation, risk-based review, corrections and rendering of the complete song video, within the scope the user authorizes in that prompt. Rendering is part of the intended outcome, not a separate workflow the user must repeatedly reconstruct.

## Remotion and optional HyperFrames scene choice

Remotion remains the master song clock and final composition/encoder. Claude has discretion to select a direct Remotion scene or a HyperFrames Player child composition per scene without asking the user to choose between those ordinary implementation routes. Use the HyperFrames route when an inspected reusable HTML/GSAP, nested-composition or footage-layering mechanism materially helps that scene. Do not treat HyperFrames as a second full-song renderer, independent audio clock or competing project. Preserve deterministic time seeking, readiness, cleanup, source/license provenance and the song's explicit frame dimensions. Follow `14_HYPERFRAMES_SUBCOMPOSITION_GUIDE.txt` and treat `shared-animation-library/examples/remotion-hyperframes-hybrid/` as evidence for its tested synchronous fixture only. The canonical production prompt excludes package installation and updates; use prepared dependencies and assets or pause for a separate dependency decision.

QUALITY AND BUDGET
Use 07_QUALITY_REVIEW_AND_ACCEPTANCE.txt. Review representative states, transitions, captions and identified risks rather than extracting every half-second automatically. Pause for genuinely missing inputs, material ambiguity that cannot be resolved with stated assumptions, purchases, credentials or actions outside the initiating authorization; avoid routine permission loops.
