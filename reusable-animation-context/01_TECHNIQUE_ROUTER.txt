CURRENT RENDER ENGINE ROUTE
Keep the song inside this connected kit and use `shared-animation-library/render.mjs`. New songs select installed Remotion with `PROJECT.renderEngine: 'remotion'`, use a song-local React `scenes` registry and put the unchanged audio and declared media in the song's `public/` folder. Existing p5 productions use the same entry through the legacy p5 route. Shared `PROJECT` timing, dimensions, cues, assets/fonts and export planning do not make React and p5 scene code interchangeable. Claude may choose a HyperFrames Player child composition per scene when its inspected HTML/GSAP or nested-composition model helps; Remotion remains the master clock and final composition/encoder. See `claude-finished-song-animation-project/14_HYPERFRAMES_SUBCOMPOSITION_GUIDE.txt` and the hybrid comparison example. Consult the two shared-animation-library READMEs for exact configuration and commands.

PER-SONG FRAME CHOICE
For each song, recommend 4:5 (1080×1350) or 9:16 (1080×1920) from its visual direction. Explain the choice before storyboarding and set explicit dimensions in that song's PROJECT config. Compose and review its scenes and overlays natively for the selected frame; do not crop a layout from the other ratio. The renderer's dimension flow is configurable; scene responsiveness must be checked separately.

PRINT, PAPER AND MIXED MATERIALS

DIMENSIONAL SCENES AND CAMERA MOVEMENT
R02 kinetic examples, R03 relevant demos and R07 architecture provide candidate WebGL/three.js paths. R10 is cinematic study material. Evaluate spatial staging, object/light/shader requirements and browser/GPU compatibility for a selected scene. Choose Canvas parallax where it achieves the visual objective; choose 3D where geometry, lighting or camera motion materially improves it.

PARTICLES, TRAILS AND EFFECTS
R06 effects, R02 examples and R03 style demos contain possible mechanisms. Inspect time/state/randomness dependencies. Closed-form trajectories and per-index seeds support arbitrary-time rendering. A source effect that depends on frame history requires a reproducible seek/reset strategy. Surface effects complement subject action and composition.

SONG TIMING AND AUDIO FEATURES
R04 music-to-video and R05 motion-graphics-music-video offer planning/audio/VFX procedures. R07 supplies audio-feature architecture; R02 painted-animation has beat-grid tooling. Read the actual analysis implementation and distinguish onsets, pulses, downbeats, subtitle times and word timing. Build the new song's cues from its own recording; reuse architecture rather than another song's timeline.

RENDERING, CACHING AND RECOVERY

PRIORITY 1 — SONG-NEUTRAL PRODUCTION SHELL (implemented 2026-10-25; static checks plus one Claude-reported local browser load of the neutral example)
Declared in PROJECT and validated by normalizeProject: productionId, modules (id, src, classic|module, requires), scenes (id, start, end, impl, needs, params; contiguous, no gaps/overlaps, exact coverage of the intended interval), cues, assets, fonts. production/production-host.mjs installProduction loads modules in stable dependency order, resolves cues/fonts/assets, initializes scene implementations, then registers them through the unmodified shots() API (scene overlays join the single overlay dispatcher at order 15). A neutral synthetic example is shared-animation-library/examples/neutral-production/. Outside the half-open coverage [start,end) no scene draws or overlays; failed installs restore the host incl. host.PRODUCTION (verified cases; a failure after shots() partially mutates cannot be rolled back). Every new production must set duration explicitly. The current production suite passes 27 non-rendering checks. Claude-reported browser readiness for the neutral p5 example is detailed in `shared-animation-library/BROWSER_READINESS_CHECK_2026-10-25.md`; no raw log was saved. By p5/project source the opening scene's draw likely ran once at startup (T=0), unobserved in a log; renderAt was never called, overlay drawing and the later hop/critter scene were not exercised. Not established: appearance, pixels, phone-size quality, saved stills, fonts and assets (example declares none), glyph coverage, audio, encoding, audiovisual review; the 8 s example does not test full-song duration or audio synchronization. Read shared-animation-library/README.md first.

PRIORITY 3 — KINETIC TYPE (separate engine route; read, deliberately NOT adapted)
R02 kinetic-reel reel.js (527 lines): lines 1-140 were read in full and lines 140-527 only as a function/comment index. The read portion hard-codes W=1920,H=1080, reads a global KCUE, sets window.DUR/PROJECT, creates its own three.js WebGL renderer on #out plus a second WebGL canvas, and swaps ctx for transition buffers. Those conflict with the shared host (2D #out, normalizeProject sizing, p5 painter). Keep it as its own entry/host (its template render.mjs). A narrow glyph-only port (letters/txt/measure helpers, math) is possible later but is not done. Do not assume the optional Lottie package supplies an asset.

PRIORITY 4 — 3D, MATERIALS AND COMPOSITING (read; separate-host routes with exact incompatibilities)
R03 risograph riso.js (154 lines): makeRiso(out,W,H) takes WebGL2 on the output canvas it is given and reads a three-plate 2D canvas; the shared #out is a 2D canvas read by toDataURL, so it needs its own canvas plus a readback/drawImage bridge that is unverified without a browser. R03 core/three/post.js makePost(renderer,scene,camera,...) needs a three.js renderer, scene and camera plus three/addons (EffectComposer, GTAO, bloom). Neither is integrated. Define canvas ownership and a verified readback path with a browser stage before bridging. Khronos RiggedSimple remains a technical fixture.

PRIORITY 5 — RECORDING-BOUND CUES AND LYRICS (cue interface defined; no analysis run)
production/cue-schema.mjs normalizeCues: source→production conversion once via numeric/timebase.mjs; evidence classes measured / estimated / inferred / supplied / confirmed; supplied lyric text (textSource 'supplied') separate from its timing evidence; optional recording id/sha256. Importers fromBeatgridAudiomap (R04 analyze-beatgrid.py output shape) and fromAudioJson (R07 audio.json shape) were written from the source code, not from real analysis output. No song has been analyzed with Librosa; WhisperX singing alignment remains unassessed.

PRIORITY 6 — LOCAL FONTS AND VISUAL ACCEPTANCE (declaration + loader implemented; no rendering; the neutral example declares no fonts or assets, so loading is unexercised by any example)
PROJECT.fonts entries ({family, src, weight, style, unicodeRange}) are loaded with FontFace before ready and hashed into cache identity. production/fontsource.mjs generates entries from the local @fontsource install (Inter 700 latin/latin-ext checked against the package CSS and woff2 magic bytes). Glyph coverage is only the package's declared unicode-range, never a cmap check. base/studio.html still references Google Fonts CSS for the legacy demo faces. Pixelmatch has no baseline. Browser/font/glyph review, phone-size stills, complete-candidate playback and audiovisual acceptance remain separate authorized stages.

INSTALLATION IS NOT INTEGRATION
Flubber, Lottie Web, Pixelmatch, selected Fontsource packages, WhisperX, Librosa and one glTF fixture are installed or locally prepared as detailed in repository-preparation/additional-resources/README.md. Most are optional and isolated; none, by itself, closes the integration gaps above. Prefer existing repo implementations where they meet the visual need, and do not install more dependencies without a named capability and scoped preparation plan.
